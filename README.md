### 🧠 whoami

I take complex, data-heavy systems — the kind with ten entity types and a thousand edge cases — and make them feel simple to use. Four years doing that for enterprise and e-commerce products, mostly living in the front end: interactive graphs, 3D viewers, real-time dashboards, the stuff that's easy to get wrong.

Lately I've been pulling the backend into my own hands too — architecture, databases, queues, payments — because the interfaces I want to build need a foundation that can actually support them. Right now that means a **commerce platform engine**: a Turborepo monorepo you can spin up fresh for a new client in minutes, each one with its own theme, its own database, its own deploy.

What excites me: systems where the architecture decision *is* the hard part — not just making something work, but making it work the second, third, and tenth time it's reused.
